# Практика 1. Знакомство с Python

Решения заданий из файла `Задачи.txt`. Проверено на Python 3.13.

## Как запустить

```powershell
python ex1-1.py
```

В VS Code: открыть папку `Практика`, нажать ▶ в правом верхнем углу.
Файлы `ex2-1.py` ... `ex2-9.py` запускать нужно специально: они сделаны
неправильно, чтобы показать ошибку из задания.

## Файлы

| Файл | Что делает |
|------|------------|
| `ex1-1.py` | число 42 двенадцатью способами |
| `ex1-2.py` | ограничения на числа int и float |
| `ex1-3.py` | функция divmod, которая возвращает два значения |
| `ex1-4.py` | почему цикл с 0.1 не заканчивается и как его исправить |
| `ex1-5.py` | почему 2 ** z зависает |
| `ex1-6.py` | почему ++i не работает в Python |
| `ex1-7.py` | почему (True * 2 + False) * -True равно -2 |
| `ex1-8.py` | цепочки сравнений 1 < x < 10 |
| `ex2-1.py` ... `ex2-9.py` | девять ошибок из задания, по одной в каждом файле |
| `ex2-summary.py` | все девять ошибок сразу, списком |

## Ответы коротко

**1.1.** `42`, `0x2A`, `0o52`, `0b101010`, `4_2`, `0x_2A`, `0o5_2`, `0b10_1010`,
`+42`, `-(-42)`, `42.0`, `4.2e1`. Это разные системы счисления, подчёркивание
как разделитель разрядов, унарный плюс и двойной минус. Знак `==` сравнивает
значение числа, а не тип, поэтому `42.0 == 42` тоже верно.

**1.2.** Целые числа (`int`) не ограничены по величине: `2**10000` спокойно
считается. Дробные числа (`float`) — это 64 бита, максимум
`1.7976931348623157e+308`. Дальше получается либо бесконечность (`1e308 * 10`
это `inf`), либо ошибка `OverflowError` (`2.0 ** 1024`). Ещё в Python 3.11+
есть ограничение на печать очень длинного целого числа (4300 цифр),
его можно поднять через `sys.set_int_max_str_digits()`.

**1.3.** `divmod(a, b)` возвращает сразу два числа: частное и остаток,
то есть кортеж `(a // b, a % b)`.

**1.4.** `0.1` — это двоичная дробь, а `1/10` в двоичной системе не пишется
точно, поэтому `a` при вычитаниях перескакивает через ноль и никогда не
становится ровно `0.0`. Условие `a != 0` всегда верно, поэтому цикл
бесконечный. Настоящее значение можно посмотреть так:
`(0.1).hex()` это `0x1.999999999999ap-4`, `Decimal(0.1)` это
`0.1000000000000000055511151231257827...`. Исправить можно четырьмя
способами, все показаны в файле: задать точное число повторов, округлять
(`round(a - 0.1, 1)`), сравнивать с допуском (`math.isclose`) или
использовать `Decimal`, где `0.1` хранится точно.

**1.5.** `z <<= 40` это `z = 2**40 = 1099511627776`. Дальше `2 ** z` это
число примерно из 3.3·10¹¹ цифр (128 ГиБ). Ошибки нет: `int` не ограничен,
поэтому вместо переполнения получается очень долгое вычисление.

**1.6.** В Python нет операторов `++` и `--`. Запись `++i` читается как
`+(+i)`, то есть как два унарных плюса, а они ничего не меняют. Поэтому
`i` остаётся нулём. Правильно писать `i += 1`.

**1.7.** `True` это 1, а `False` это 0 (тип `bool` в Python является подтипом
`int`). Получается `(2 + 0) * (-1) = -2`.

**1.8.** `1 < x < 10` это цепочка сравнений, то есть `1 < x и x < 10`,
поэтому True. Скобки всё поменяли: сначала считается `x < 10`, это True
(то есть число 1), потом сравнивается `1 < 1`, это False.

**2.** Ошибки SyntaxError и IndentationError означают, что код неправильный
и программа не запускается вообще. Ошибки NameError, TypeError, ValueError
и OverflowError появляются уже во время работы программы.

Тексты сообщений немного отличаются в разных версиях Python. Например,
в Python 3.13 к `cannot assign to literal` добавляется подсказка
`Maybe you meant '=='` — это нормально, важен сам тип ошибки.
